## What Astra is

A local-first agentic IDE: React frontend, Express backend, agent loop that drives
Ollama (or OpenAI/Anthropic/Gemini) with filesystem and terminal tools. Monaco
editor, PTY terminals, shadow-git checkpointing.

**Branch:** `feat/server-side-agent-loop` (pushed to `RRG2022/Astra-CC`)
**Tags:** `v0.6.0` → `v0.9.1`
**Tests:** 154 backend (`cd backend && npm test`), 16 e2e (`cd frontend && npx playwright test`)

## Environment (matters — it bit us)

The repo lives on a **Windows** machine. The previous session ran on a **Mac**
connected over **SMB** (`/Volumes/192.168.10.1-2/Astra`). SMB gives file access
only — commands executed on the Mac, not on Windows. Ollama exists on both.

- ~~`node_modules` is shared across both platforms and that is **safe**~~ —
  **this was wrong.** It holds for the backend (`node-pty` ships prebuilds for
  all targets), but the **frontend has three platform-native bindings**, each
  installed only for the platform that ran `npm install`: `@rolldown/binding-*`
  (Vite 8 is rolldown-based), `lightningcss-*`, and `@oxlint/binding-*`. A
  darwin-only install makes `npm run dev` die at startup on Windows with
  "Cannot find native binding". Installing the win32 ones prunes the darwin
  ones — one `node_modules` cannot serve both machines. Whichever platform is
  in use runs `npm install` in `frontend/`.
- Git warns `remote repository ... is incompatible with fsmonitor` on every
  command. Cosmetic; ignore.
- Dot-files that arrived from the Mac over SMB carry the Windows **Hidden**
  attribute. `fs.writeFileSync` over a hidden file fails `EPERM`; `renameSync`
  over one succeeds. Every writer in the app now uses temp+rename, which is
  immune — keep it that way rather than adding plain overwrites.

## Where the project was, and what changed

Three milestones landed this session, each a commit and a tag.

### v0.6.0 — the server-side loop actually runs (`45e5085`)

The prior commit ("Phase 1") had moved the agent loop server-side but was
committed without an end-to-end run. **It could not complete a single turn.**
Five blocking defects, all fixed:

1. **Internal 401s.** The runtime called its own HTTP API without the launch
   token, so every model call and every tool call 401'd — and the failure was
   reported to the client as `stopReason: complete`. Fixed by construction:
   tool bodies moved to `src/tools/` and provider adapters to `src/llm/`, both
   called in-process. There is now no self-call over HTTP.
2. **Approval deadlock.** `pendingApprovals` was keyed on an id Ollama never
   supplies; the UI showed a different generated id; the frontend never called
   approve/deny at all. One canonical `callId` is minted in `resolveToolCalls`
   and used for the approval key, the UI card, and `tool_call_id`.
3. **Message index off-by-one.** Server counted the system turn, client didn't.
   Events are now keyed by an assistant message id the client mints.
4. **Tool-less default model.** Tools were attached by matching `llama|gpt` in
   the model name, so the default (qwen) got no schemas. Now probed via
   `/api/show`.
5. **Dead test suite.** Both unit files imported modules that had moved; all
   four e2e specs mocked the deleted client-loop boundary.

Also fixed: a retired Anthropic model id (`claude-3-opus-20240229`) and its
`tool_use_id: 'unknown'` placeholder, which made every Claude tool round-trip
fail; and a missing `getWsUrl` import crashing the terminal pane.

### v0.7.0 — trustworthy over long tasks (`963aba5`)

- **Context budgeting.** The window was hardcoded `8192` for every model; now
  read per-model from `/api/show` (qwen2.5-coder:14b reports **32768**) and fed
  back as `num_ctx`. Two-stage compaction at 70%: evict old tool-result bodies
  first (leaving a marker telling the model how to re-fetch), then digest oldest
  turns. **Every cut is at a user boundary** so tool results are never orphaned
  from their calls — providers reject that outright.
- **Tool results capped** before entering context, trimmed field-wise so
  truncation never destroys the `contentHash` that `edit_file` preconditions on.
- **Project awareness.** `AGENTS.md` / `CLAUDE.md` / `.agents/AGENTS.md` loaded
  into the system prompt. The prompt is built **server-side** so a client cannot
  drop project rules or widen a persona.
- **Personas carry a tool allowlist** enforced at session build. `app_admin` was
  told in prose never to write code while holding `write_file`; now it has no
  write tools.
- **`read_file` offset/limit** implemented — the schema had advertised slicing
  the handler ignored.
- **Session persistence** under `.astra/sessions` with resume, list, delete, and
  idle eviction.

### v0.8.0 — unattended running (`e7d60c2`)

- **Permission rule engine.** Pattern rules in `.astra/permissions.json`:
  `allow run_command npm test*`, `deny write_file secrets/**`. Authority level
  remains the fallback. **`deny` cannot be shadowed** by a later allow, by
  Autonomous, or by `--yes`.
- **Audit log.** Append-only `.astra/audit.jsonl` — every call, its decision,
  the rule behind it, the outcome. Args recorded by size, not copied.
- **Plan mode.** A capability filter, not a prompt convention: mutating tools
  are absent from the request. Composes with persona limits.
- **Headless CLI** `backend/bin/astra.js`. Exit codes distinguish completed /
  error / blocked-on-approval / hit-the-cap. Unattended, a call that would
  prompt is **refused rather than left hanging**, printing the rule that would
  unblock it.
- Tool schemas moved to the backend (`src/tools/schemas.js`), which owns the
  registry that executes them.

### v0.8.1 — two bugs found by driving a real model (`bb130a5`, `0a720b3`)

Neither was findable by reading code or from the fake-model harness:

- **Fenced tool calls were discarded.** qwen2.5-coder asks by writing a
  ` ```json ` fence containing the call and nothing else. The rule now turns on
  whether there is *prose around* the fence: a lone fenced call is intent and is
  honoured; a fence embedded in explanation stays gated (that is the original
  prose-execution/RCE bug the guard exists for).
- **Permission rules silently didn't match on Windows.** `subjectOf` compared
  the model's raw path, so `src\utils\a.js` never matched a rule of `src/**`.
  Path subjects are now normalized. **Directly relevant to this deployment.**

1. **The suite hung and was killed at the 20s per-test timeout.** All 30

### A fourth bug, found by watching the UI

qwen2.5-coder's habit is to announce the action and then fence the call:
"Now, I will write this summary to a file called summary.md." followed by a
` ```json ` block. That shape is correctly **not** executed — prose around a
fence is the RCE case the guard exists for. But `resolveToolCalls` stripped
*every* parsed span from the displayed content, including the one it had just
refused. The user saw the model state it was writing a file, no tool card, no
file, and `stopReason: complete` — exactly the class of silent-success failure
this codebase is built to avoid.

A span is now removed only when the call inside it is actually going to run
(matched by `callKey`, so a text copy of a native call is still hidden). A
refused call stays visible in the reply. The guard itself is unchanged.

Done in v0.9.1 — see below.

### And a fifth, from asking for two tools at once

Given a prompt needing two calls, qwen answers with two ` ```json ` fences back
to back and **no prose at all**. The v0.8.1 rule keyed on `match[0] === text` —
a *single* fence filling the message — so each of two fences looked like
documentation and the turn did nothing.

The rule now keys on what it always meant: a message that is *nothing but*
fenced calls has no explanation for them to be documenting, whether it holds
one fence or three. Any prose outside the fences, or a fenced block that is
ordinary JSON rather than a call, and they all stay gated.

## v0.9.0 — Milestone 2 complete (sub-agents, task list)

### Sub-agents with isolated context

**The design decision the previous handoff left open — how a child's results
re-enter the parent's context — is: they do not.** The child's final assistant
message is the entire return value. Nothing else survives.

That is the whole reason to spawn one. A survey that takes twenty tool calls
costs the parent one message instead of twenty, and it only works if the
transcript is genuinely discarded rather than summarized into the parent.

Three properties the implementation must not lose, each tested:

- **A child can never do more than its parent.** `resolveChildTools` intersects;
  it cannot widen. A plan-mode parent asking for a `write_file` child gets an
  error, not a writing child. This is the security property — without it,
  spawning is an escape hatch from plan mode and from persona allowlists.
- **A child cannot spawn.** `spawn_agent` is removed from the inherited set, so
  recursion is bounded by construction rather than by a depth counter.
- **A child's approvals are the parent's approvals.** `requestApproval` passes
  straight through, its calls hit the same rules, and the audit log tags them
  `agent: "sub:<callId>"` against `"main"`. Cancelling the parent cancels
  children — `AgentRuntime.children`.

A child that stops early returns `success: false` with its `stopReason`. A
capped sub-agent has findings, not an answer, and the parent must not read the
two the same way.

### Agent-maintained task list

`update_tasks` takes the **whole list every call** — no deltas. So the most
recent result in context is always the complete state: nothing to merge, and no
way for the model's plan to drift from the one the user is watching. At most one
task may be `in_progress`; a list where everything is in progress is not a plan,
and it is the shape a model drifts into when nothing stops it. Rejections come
back as repairable tool errors, so a bad list costs a round-trip, not the turn.

Rendered as the PLAN panel above the composer, persisted with the session, and
returned by `GET /api/sessions/:id`.

### And the frontend stopped shipping its own tool schemas

`frontend/src/lib/constants.js` held a second copy of every schema and sent it
on session creation, which **overrode** the backend's. The new tools would
never have reached the model through the UI. The client now sends none — the
backend owns the schemas because it owns the registry that executes them. This
is the same drift that once had `read_file` advertising slicing it did not do.

## v0.9.1 — the announce-then-fence no-op

The last shape still silently doing nothing. qwen2.5-coder writes:

> I have read `readme.txt`. Now, I will write a file called `overview.md`.
>
> ` ```json ` `{"name":"write_file", …}` ` ``` `

Prose around the fence, so the guard declines it — correctly, that is the
prose-execution case. But the turn then *ended*: `stopReason: complete`, no
tool card, no file, and the model's last words claiming it had written one.

**What the driving run showed.** Feeding the refusal back as a correction was
the obvious fix, and it was not enough. qwen never makes a native call — it
only ever writes fenced JSON. Corrected, it replies *"I apologize for the
confusion. I will proceed with the `write_file` tool"* and writes **the
identical fence again**. Twice. Then the correction budget ran out and the file
still did not exist.

So the rule is now: **the correction is the disambiguator.** The guard cannot
tell a model asking for a tool from one illustrating it — that is exactly why
it declines. Being asked, and answering, is what resolves it. A call refused
last turn and written again, after being told it did not run, is the model
saying which one it meant, and it runs.

What is deliberately *not* relaxed:

- Confirmation is keyed on `callKey` — tool **and** arguments. A different call
  after a correction is not run on sight; one nudge does not unlock text calls
  for the rest of the turn.
- It covers only the turn immediately after the correction that asked for it.
- **Every other gate still stands.** Authority level, permission rules and the
  approval prompt are untouched. Confirmation answers "did you mean it", never
  "may you" — a confirmed `write_file` under Supervised still asks the user.
- Still capped at `MAX_TEXT_CALL_CORRECTIONS` (2), so a model that keeps
  producing *new* text calls cannot spend the whole iteration budget.

Live, same prompt that produced nothing before: one correction, the model
repeated the call, it ran, `overview.md` written.

## Still open

**Known-deferred (documented, not accidental):**
- `/api/problems` runs `npx eslint` with a request-controlled `cwd`
  (`src/app.js`). Behind auth+origin now, so not critical; pin to a resolved

- `workspacePath` is still a request field rather than pinned session state.
  Contained by `resolveSafePath` and only reachable with the launch token.

  many requests per second in the backend log. Cosmetic, but it buries real
  entries; fix when the plugins panel is next touched.

## Architecture notes worth not re-deriving

- **The agent never calls its own HTTP API.** `AgentRuntime` calls `executeTool`
  and `streamChat` in-process. `/api/chat` and `/api/tools/*` are thin wrappers
  over the same functions for external consumers. Keep it that way — the
  original 401 bug was a symptom of the loop talking to itself over the network.
- **One canonical `callId`** flows through approval key → UI card →
  `tool_call_id` → audit log → a sub-agent's `auditAgent` label. Minted in
  `toolProtocol.resolveToolCalls`.
- **A sub-agent returns its last message and nothing else.** Do not be tempted
  to splice its transcript into the parent "for context" — that gives back
  exactly the window pressure the feature exists to remove.
- **A text-shaped call is never executed on sight from inside prose.** It runs
  only after the model has been told it did not run and has asked again for the
  same call with the same arguments. Do not "simplify" that into trusting
  fenced calls generally — the guard is what stops an explanation becoming an
  action.
- **Capabilities only ever narrow.** Persona ∩ mode ∩ requested-child-tools.
  Every layer filters; none of them adds. Anything that grants a capability
  further down the chain is a bug, not a feature.
- **The browser is a viewer.** It posts a message, watches SSE, answers approval
  requests. It does not run the loop and does not build the system prompt.
- **Never report a failure as completion.** `stopReason` ∈
  `complete|cancelled|denied|max_iterations|error`. The July audit's worst class
  of bug was a dead backend rendering as a successful empty turn.
- **Test seams:** `backend/test/fakeOllama.js` is a scriptable Ollama stand-in
  (supports fragmented tool-call args and mid-line TCP splits);
  `backend/src/app.js` exports `createApp()` so the server boots on an ephemeral
  port with no side effects. Frontend e2e mocks `/api/sessions/*` including SSE.
